## 6. Prolongation aider à 4 tours — écart assumé au harnais officiel

Demandé : *« @turn 4 si turn 2 fails, on conserve l'historique du tout »*.

Ce que le harnais fait déjà tout seul : `Coder.create(...)` est appelé **une
fois**, avant `for i in range(tries)`, et rien ne remet l'historique à zéro dans
`benchmark.py`. `--tries 4` conserve donc nativement la conversation.

Ce qu'il fallait ajouter : aider **résume** dès que l'historique dépasse
`max_chat_history_tokens` (valeur effective mesurée ici : 8192). Aux tours 3 et
4, les tours précédents auraient été vus en résumé. C'est un attribut *runtime*
du `Model`, ni un champ `ModelSettings` ni une option du banc — d'où la
surcharge dans `benchmark.py` :

```python
main_model.max_chat_history_tokens = 1_000_000
dump(main_model.max_chat_history_tokens)
```

**C'est un écart au harnais officiel, et il se déclare.** Le `dump` porte la
valeur effective dans le journal de chaque run.

Vérifié au smoke `python/bowling` (`--verbose`) : `[false, false, true]`,
50 362 jetons de prompt sur 3 tours contre 18 051 sur 2, **zéro** résumé,
zéro fenêtre épuisée, 100 % de réponses bien formées.

## 12. Pilote dsh sur le corpus polyglot — construit et calibré

`scripts/polyglot_dsh/pilote.py` et `scripts/polyglot_dsh/calibrer.py`.

dsh tourne sur l'hôte, les chaînes de test vivent dans l'image
`aider-benchmark` ; les deux voient les mêmes fichiers parce que
`tmp.benchmarks` est monté. L'agent édite sur l'hôte, le juge s'exécute par
`docker exec` dans un conteneur dormant.

Repris au harnais officiel au paramètre près : assemblage de la consigne,
choix des fichiers éditables, restauration des solutions, **recopie fraîche des
tests + retrait des `@Disabled` Java avant chaque verdict**, commandes de test
par langage, délai de 180 s, message `test_failures`, gommage des durées.

**Calibrage (sans modèle ni GPU) — passé :**

```
corpus : cpp 26  go 39  java 47  javascript 49  python 34  rust 30  = 225
consigne : addendum present, editables = bowling.py / forth.go / lib.rs
juge : 3/3 souches VIERGES echouent, comme elles le doivent
```

Ce dernier point est le contrôle central : si une souche vierge passait, le juge
ne jugerait pas et tout le banc serait faux.

### Trois écarts à déclarer, inhérents

1. **L'historique.** aider garde la conversation littérale entre les tours.
   `dsh --profile headless` répond à une tâche puis sort — pas de session. Ici
   la mémoire est l'**espace de travail** : au tour 2 l'agent relit le code
   qu'il a écrit et les erreurs de test, pas sa propre prose.
2. **L'échantillonnage.** aider force temp 1.0 / top_p 0.95 / top_k 20 / min_p 0
   par `--read-model-settings` ; dsh envoie ce que sa route définit.
3. **Le prompt système** de chaque agent, non neutralisable sans dénaturer
   l'agent mesuré.

Ce pilote compare donc **deux agents** sur le même corpus et le même juge —
pas deux modèles toutes choses égales.

### Le défaut que le premier échantillon a révélé — et pourquoi il est grave

Premier échantillon (un exercice par langage, 2 tours) : **6 FAIL sur 6**, en
1,1 s par tour. Un agent ne travaille pas en 1,1 s. Sonde manuelle :

```
dsh: MISSING_CREDENTIAL: llm-pi-ai: no credential for provider route
"local-think"; its profile resolves DSH_LOCAL_API_KEY, which is not set
```

L'accueil isolé ne contient que `settings.yaml` ; la route **déclare** un
`apiKeyEnv`, et dsh refuse de démarrer si la variable n'existe pas. Le banc
Julia s'en sortait par une ligne que je n'avais pas reprise :

```python
env.setdefault("DSH_LOCAL_API_KEY", "local-loopback-noauth")
```

La valeur n'a aucune importance — l'amont est notre llama-server en boucle
locale, qui n'authentifie rien. C'est un jeton nominal. **Aucun
`~/.dsh/.credentials.yaml` n'est copié** : un fichier de clés ne se recopie pas,
il se charge par l'environnement.

**Pourquoi ce défaut est le plus dangereux de la nuit.** Un agent qui ne démarre
pas rend `FAIL` partout. Sur 225 exercices, ça aurait donné un **« 0 % »
parfaitement présentable et entièrement faux**, impossible à distinguer d'un
mauvais modèle. Deux garde-fous ajoutés :

1. **Pré-vol** : avant de jouer quoi que ce soit, le pilote demande à l'agent de
   répondre `PREVOL-OK`. S'il ne répond pas, il **refuse de partir** et imprime
   les dernières lignes de la sortie.
2. **La queue de la sortie de l'agent est enregistrée** à chaque tour dans
   `.dsh.results.json`. Il a fallu relancer dsh à la main pour lire l'erreur —
   un banc doit porter sa propre explication.

Les fichiers du premier échantillon sont **conservés** (`dsh-polyglot-echantillon`)
plutôt qu'effacés : ils sont la trace du défaut. La reprise tourne sous un nom
neuf.

198 cas à 4 tours. Le contrôle disait ce qu'il mesurait ; c'est moi qui l'ai

### Le défaut qui interdit la comparaison : l'agent lance les tests lui-même

`scratchpad/preuve_boucle.py` cherche dans la queue de sortie de l'agent les
formulations qui n'ont de sens que s'il a **vu une sortie de test** :

```
exercices dont la sortie prouve qu'il a lance les tests : 20 / 38
```

et c'est un **plancher** : la queue ne garde que 600 caractères du dernier
message de chaque tour. Extraits :

- `cpp/phone-number` : « *Deleted the old build/ directory. Reconfigured CMake
  fresh: cmake -S . -B build -DEXERCISM_RUN_ALL_TESTS=1. Built and ran the
  tests. Result: All tests passed (18 assertions in 18 test cases)* »
- `python/beer-song` : « *All 8 tests passed. The task is complete.* »

**Ce que fait aider dans le banc polyglot** : le modèle écrit le fichier **à
l'aveugle**. Il ne voit jamais le fichier de test, ne compile pas, n'exécute
rien. C'est le harnais qui lance les tests *entre* deux tours et lui renvoie la
sortie d'échec.

**Ce que fait dsh dans mon pilote** : il a un shell. Il lit le test, compile,
lance la suite, corrige, relance — **autant de fois qu'il veut à l'intérieur
d'un seul tour**.

> **Conclusion : 92,1 % et 52,5 % ne mesurent pas la même chose.** Ce n'est pas
> un écart de modèle — c'est le même modèle. C'est un écart de **boucle**. Le
> 92,1 % est une mesure honnête de ce que fait dsh ; il n'est opposable ni au
> 52,5 % d'aider, ni au board Aider. Le « tours moyens : 1,13 » le dit d'ailleurs
> tout seul : l'agent n'a presque jamais besoin d'un 2ᵉ tour, parce qu'il a déjà
> bouclé à l'intérieur du 1ᵉʳ.

### Défaut secondaire : `.meta/example.*` est lisible

`scratchpad/fuite_solution2.py` compare le plus gros fichier solution produit à
la référence (texte normalisé : sans commentaires, sans blancs).

```
sur les 35 fichiers d'au moins 400 caracteres :
  mediane 20.1 %   max 100.0 %   >80% : 3
```

- **`cpp/phone-number` : 100,0 % sur 1 295 caractères** — copie littérale de
  `.meta/example.cpp`. Ininterprétable autrement à cette taille.
- `python/beer-song` 93,6 % (697 car.) et `python/dot-dsl` 80,7 % (1 022 car.) :
  ambigus, ces deux sujets dictent fortement leur sortie.
- Médiane 20,1 % : **ce n'est pas une copie généralisée.** La fuite n'explique
  pas le 92,1 % ; la boucle de test si.

Le corpus expose aussi `.approaches/*/snippet.txt` — des solutions commentées.
aider ne les lit jamais (format `whole`, ni repo-map ni shell) ; un agent avec
`ls` et `read`, si.

### Mon propre défaut de mesure, rectifié

Premier passage : j'ai annoncé `cpp/yacht` à **100 %** de similarité. Faux —
mon script prenait le **maximum** sur tous les fichiers solution, ce qui a
sélectionné `yacht.h`, un en-tête de **9 lignes** (`#pragma once`, deux
`#include`, une signature) dicté par le sujet. Comparé au vrai fichier
d'implémentation `yacht.cpp` (1 541 car.) : **38,6 %**. Une similarité ne se lit
jamais sans la taille du fichier.

### Défaut de harnais : collision de `build/` hôte ↔ conteneur (C++)

Les **deux** échecs cpp portent la même signature. L'agent configure et compile
sur l'hôte Windows ; le juge recompile dans le conteneur Linux ; `CMakeCache.txt`
garde des chemins absolus. `cpp/phone-number` a copié la référence, l'a fait
passer **sur l'hôte**, et a quand même échoué **au juge**. Correctif à faire :
effacer `build/` avant l'exécution du juge, ou empêcher l'agent de compiler dans
le répertoire que le juge utilise.

### Ce qu'il faudrait pour rendre les deux chiffres comparables

Au choix, et ce n'est pas un détail de réglage :

1. **Retirer la boucle à dsh** — lui interdire d'exécuter les tests (workspace
   sans le fichier de test, tests reposés seulement au moment du juge). Mesure
   alors le même objet qu'aider, mais mesure dsh amputé de ce qui en fait un
   agent.
2. **Donner la boucle à aider** — hors du protocole du board.
3. **Assumer deux mesures distinctes** et ne jamais les mettre dans la même
   colonne. C'est l'option honnête par défaut.

Dans tous les cas : **masquer `.meta/**` et `.approaches/**`** du workspace de
l'agent, ce qui est un correctif sans contrepartie.

## 17. Variante B préparée — l'agent sans le fichier de test

### Pourquoi B n'est PAS « la version comparable à aider »

Correction d'une phrase que j'avais écrite : *« ~13 h, et c'est la seule version
opposable au 52,5 % »*. **Faux.** Deux choses distinctes ont été confondues :

| ce que dsh a en plus | nature |
|---|---|
| **lire** le fichier de test | il voit le barème : assertions, messages d'erreur, cas limites |
| **compiler et exécuter** | il a un compilateur et un lanceur de tests |

Retirer le second estropie un agent. Retirer le premier est une autre
expérience — et pas une brimade : Exercism donne le fichier de test à ses
apprenants, c'est sa pédagogie.

| variante | voit le test | peut exécuter | mesure |
|---|---|---|---|
| A — banc aider | non | **non** | le modèle, à l'aveugle → **52,5 %** |
| B — nouveau | non | oui | l'agent, sans le barème |
| C — pilote actuel | oui | oui | l'agent complet → **92,1 %** |

**Il n'existe pas de variante de dsh opposable au 52,5 %**, sauf à le
transformer en aider. B répond à une autre question, et c'est celle qui vaut la
mesure : *l'agent résout-il le problème, ou s'ajuste-t-il aux assertions qu'il a
sous les yeux ?* L'écart entre 92,1 % et B est exactement cette part.

### Implémentation

`pilote.py` gagne deux drapeaux **séparés** — les mélanger rendrait l'écart
inattribuable :

- `--sans-tests` : le fichier de test quitte l'espace de travail **pendant le
  tour**, et revient pour le juge ;
- `--sans-corriges` : masque `.meta/**` (dont `example.*`) et `.approaches/**`.

Mécanique : `masquer()` / `demasquer()` par **déplacement** vers un stash hors
de l'exercice, jamais par suppression ; le démasquage est dans un `finally`,
pour qu'un tour qui lève ne laisse pas un exercice amputé que le juge noterait.
La variante est écrite dans chaque `.dsh.results.json` (`"variante": "B"`) —
sans ça, deux runs deviennent indiscernables et on finit par comparer B à C sans
le savoir.

Limite déclarée : le stash est ailleurs dans l'arborescence montée, pas sur un
autre système de fichiers. Un agent qui remonterait délibérément les répertoires
parents le retrouverait. On mesure un agent qui travaille, pas un agent qui
triche.

### Calibrage — `calibrer_masque.py`, sans GPU

Le risque de B est précis : si `demasquer` échoue, le juge tourne sur un
exercice **sans fichier de test**. `go test ./...` sort alors en **code 0** et
`pytest` en code 5. Un run entier rendrait un « 100 % » présentable et
entièrement faux — le défaut MISSING_CREDENTIAL sous une autre forme.

```
=== python/affine-cipher / go/alphametics / rust/accumulate / cpp/all-your-base
  1. masque         : tests absents 1/1 ; .meta parti True
  2. demasque       : arbre identique octet pour octet : True
  3. tour qui leve  : exercice intact apres le finally : True
  4. souche vierge  : le juge ECHOUE (attendu)

CALIBRAGE OK sur 4 temoins
```

Le contrôle 4 est celui qui décide : après un cycle complet, une souche vierge
doit **toujours** échouer. Si elle passe, le juge ne juge plus.

### Une confusion à ne pas commettre au lancement

`--sans-tests` **seul** est piégeux : privé du fichier de test, l'agent peut se
rabattre sur `.meta/example.*`, qui reste lisible. Le taux resterait haut pour
la mauvaise raison et l'écart avec 92,1 % serait sous-estimé.

Décision : **B se lance avec les deux drapeaux.** La fuite du run C est déjà
mesurée (1 copie littérale sur 38, médiane 20,1 %), assez petite pour que
l'écart s'attribue principalement au fichier de test. Si l'écart s'avère
important, un run de contrôle `--sans-corriges` seul (~2 h) sépare les deux.

### Commande

```
python pilote.py dsh-polyglot-B-p6 --tours 2 --pas 6 --effort medium \
       --sans-tests --sans-corriges
```

`--pas 6` reproduit **exactement les mêmes 38 exercices** que le run C : le pas
est déterministe sur le corpus trié. Même échantillon, même juge, un facteur.

NON LANCÉ : la carte est prise par la reprise aider (conteneur
`aider4tours-r4`, 27 exercices restants).

## 18. GPQA Diamond — le Q4 local contre le chiffre publié (26/08)

### La question posée

*Mon modèle local répond-il aussi bien ?* Référence : **GPQA Diamond 89,2**,
chiffre Alibaba de la carte modèle Qwen3.8-27B du 14/08/2026. Objet mesuré :
le même modèle en **Q4_K_M** servi par llama.cpp sur :8005 (specdec dflash2,
KV q8/q4, ctx 163 840).

### Le jeu de données

GPQA Diamond est *gated* chez l'auteur et aucun jeton HF n'est présent ici.
Passage par un miroir CC-BY (`Wanfq/gpqa`) : **198 lignes**, colonnes
canoniques (`Question`, `Correct Answer`, `Incorrect Answer 1..3`, `Subdomain`,
`Record ID`). Vérifié, pas supposé.

### Deux choix de mesure, déclarés

**1. Rotations.** Chaque question est posée 4 fois, la bonne réponse occupant
tour à tour A, B, C, D, les distracteurs tournant avec elle. Deux effets :

- le biais de position disparaît **exactement** de l'agrégat, et se mesure
  (table par lettre) ;
- n passe de 198 à **792**, ce qui ramène 1 σ de ~3,6 à ~1,8 point.

Sans ça, l'écart cherché est sous le bruit — la leçon du contrôle `high`
/`xhigh` du banc Julia, où n=10 ne séparait rien.

**2. Ordre des questions brassé** (graine fixe), les 4 rotations d'une question
restant groupées. Un run interrompu reste donc un échantillon **aléatoire non
biaisé ET équilibré en position**. Un run partiel se lit.

### Ce que le dépouillement REFUSE de faire

Il ne donne pas un σ binomial sur 792 tirages. Les 4 rotations d'une même
question sont corrélées : une question que le modèle ne sait pas, il la rate
4 fois. Traiter 792 tirages corrélés comme indépendants divise l'erreur
affichée par ~2 et fabrique une précision qui n'existe pas. **L'erreur publiée
est groupée par question** (écart-type des 198 moyennes / √198).

### Le piège qui a failli passer : la quantification du fournisseur

Pour le réglage du harnais, `qwen/qwen3.8-27b` est appelé sur OpenRouter.
Interrogation du catalogue des points d'accès :

| quantification | fournisseurs |
|---|---|
| **bf16** | **AkashML — seul** |
| fp8 | Chutes, CoreWeave, Reka, Venice, Parasail, Io Net |
| inconnue | Phala, Alibaba, Cloudflare |

**Huit chances sur dix de mesurer du fp8 en l'appelant pleine précision**, en
silence. Épinglage `{"quantizations": ["bf16"], "allow_fallbacks": false}` —
et le fournisseur ayant *réellement* servi est enregistré à chaque ligne.
Épingler dans la requête ne prouve rien ; seule la réponse prouve.
Mesuré : `{'AkashML': 14}` sur les 14 premiers appels.

### Le critère d'arrêt du réglage, fixé AVANT

OpenRouter sert à corriger des **défauts mesurables** — non-parse < 1 %,
troncature < 1 %. **Le score n'est pas un critère.** Choisir une variante de
harnais parce qu'elle rend un meilleur chiffre, c'est desserrer la barre.

Corollaire de conception : la réponse brute de chaque appel est stockée, donc
une correction d'extraction se réapplique **rétroactivement** sans relancer
un seul appel. C'est ce qui permet de faire tourner le local en même temps
que la mise au point.
